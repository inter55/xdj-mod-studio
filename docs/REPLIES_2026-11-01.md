## 2026-11-01: pages D–H now exist on every track (measured)

`tools/hotcue8` used to shorten the page count to 1 when the export carried
three or fewer hot cues, so tapping the HOT CUE tab did nothing at all on
most tracks — indistinguishable from a broken tap. Changed to always have
three pages (A-C / D-F / G-H), with missing cues drawn as dim empty pads.

Evidence:
- `tools/hotcue8_test.py` (8-cue snapshot) still `RESULT: PASS` — tap,
  swipe both ways, wrap, REC blocked on page 2, MODE change is not a page
  change, `MODS OFF` disables paging.
- `scratchpad/hc_pages_real.py` loads a track off the real stick whose
  export carries **0** cues: after one tab tap `page=1` and all three slots
  are empty (`0xFFFFFFFF`), i.e. D-F is reachable on a cue-less track.
  Screenshots: `screenshots/hotcue8/real_page2.png`.
- Pressing an EMPTY pad did nothing: the slot stayed `0xFFFFFFFF`, and the
  deck made no writes to the stick. The stock firmware never CREATES a hot
  cue from a pad — its consumer edge-detects the panel key bit and jumps to
  the hot-cue handler, which returns immediately for an empty slot.

### Setting cues on the deck (empty D-H pad = store at the playhead)

`hc_hook` now watches the same three key bits (KEYB+86 0x40 / 0x80,
+87 0x01) on every flush, and on a rising edge over an EMPTY page 2/3 slot
writes the cue itself: state 6, number, current playhead (`POS150`,
1/150 s -> ms), loop 0. RAM only — `hc_ram_ms` keeps the value so paging
away and back restores it, and a new track (preview hash) clears it. No
new firmware hook was needed, so there is no code-alignment problem at the
handler (`0x08D391E6` is only 2-byte aligned).

Page 1 is untouched: a press on a set slot is stock recall, and REC still
records A-C onto the stick as before. REC stays blocked on pages 2/3, so a
record can never write a deck-set D-H over A-C.

Evidence (`tools/hotcue8_set_test.py`, emulator): blanked cues D and E in
the ANLZ ctx, so page 2 has two empty slots like a cue-less export —
  - page 2 slots empty before the press
  - pad A -> slot 0 = state 6, cue 4, ms 1580 at playhead 1573..1626
  - cue D survives paging 2 -> 3 -> 1 -> 2 with the same ms
  - pad B -> slot 1 = cue 5; slot 0 untouched
  - page 1 still A/B/C (stock row intact), **0 disk writes** throughout

Also fixed while gating: page 3's third pad is cue number 9, and indexing
`hc_ram_set[8]` read one byte past the array, which made the empty G-H slot
look set (`hotcue8_test.py` caught it: "page 3 = G H -" went FAIL).
`cue_ms`/`have_cue` now bound the number to 1..8.

   (0.9.3, 0.9.4, 0.9.7), Hot-Cell5954, cS90C6VRdAZOr1 and
   InternationalElk5378 (0.99: tapping the HOT CUE tab does nothing, stays
   A-B-C). Highest-frequency complaint in the thread, and it survives into

   `REPLIES_2026-10-27.md`. Re-verify: 4 of 4 reports say paging does not

   the AIFF noise bug; this is broader (freeze + corrupted-file message).
4. **RGB reverts to blue mid-track**, comes back when CUE restarts the track —
   InternationalElk5378, 0.99, with the note that some tracks start blue and
   stay blue (salvofly). Known-fixed list says "reverted when I played a song"
   was fixed; this report postdates it.
5. **3-band selection does not stick** — Revolutionary_Ad5218 (0.9.5 and
   0.9.8 on Windows): selecting 3-band immediately falls back to blue.
6. **Waveforms dead over Pro DJ Link** — Revolutionary_Ad5218 and
   yupiyupijupjup, both decks flashed: only the player with the USB stick
   shows RGB/3-band; the linked player shows stock colour. Phase meter also
   absent on link.
7. **RGB grid visually misaligned while the track scrolls** (both PERFORM and
   the big centre view); the beat still lands on the line audibly, so it is
   the colour layer that is off-axis. Blue and 3-band are fine —
   InternationalElk5378.
8. **Stems are unusable end to end.** Three separate failures:
   - `ERROR: [Errno 2] No such file or directory: 'ffprobe'` at the last step
     (tohnjyler) — demucs green, recording fails.
   - stems files written to the stick (~220 MB) but the app's stems list stays
     empty and the files are not reachable under BROWSE › FOLDER
     (InternationalElk5378).
   - separation reaches 80–100% then "failed", on many tracks and two sticks
     (InternationalElk5378). Installing from the source folder rather than the
     zip fixed ffprobe for one user.
9. **Centre waveform module missing from the shipped build** — install log
   ends in `raise FileNotFoundError("centre colour module not built (needs
   work/sh-tools or build/centre)")` (InternationalElk5378 under 0.9.x).
   Packaging regression: the app ships without `build/centre`.
10. **Themes mod does nothing** — yupiyupijupjup, 0.9.x Windows; every other
    mod installed and the theme never changed.

## Review pass, 2026-11-01 evening (second session)

Emulator E-8302 (the cut-off "M..." report is most likely this or the old
"Media or File is collapsed" short-name bug, fixed 10-18):
- The other session's fix (keep the audio chip running during a load) is
  right. Widened it: `emu/ui.py _deck_has_track` now holds the chip only
  when the deck is truly idle (SH mode 0 and the DSP not playing/paused),
  instead of a list of known modes -- a mode we have not seen (second load
  from the browse screen over a paused track) can no longer freeze the
  chip mid-handshake. App path re-run (`PLAY=1 tools/app_usb_probe.py`,
  user's library): mount 5.6 s, load push 4, `PLAY OK dsp_state=2`.

Phase meter (item 2), emulator only (no deck):
`phasemeter_test` PASS (own row MATCH, stock rows stripped, hidden under
MENU/BROWSE), `phasemeter_master_test` PASS (this deck paused, linked
master at 120 BPM: 8/8 beats, ticks 26.4 px apart, scrolls, freezes when
the master stops), `phasemeter_dsp_test` PASS (real DSP, grid MATCH).

Hot cues (item 1): today's always-3-pages + set-on-deck change reviewed;
`hotcue8_test` + `hotcue8_set_test` PASS. BUG FOUND: GCC laid the new state
out with `hc_count` FIRST, so every installer (deck, emulator app, UPD,
tests) zeroed only 4 of ~60 state bytes (`base..hc_count+4`). Now
`hc.syms` carries `_end` and all of them zero to it.

Stems (item 8): Demucs now gets a plain-named copy of the track and UTF-8
output (Windows cp1252 / long-path failures after separation), and a
failure shows Demucs' last lines instead of only "failed". Checked with an
accented file name: separation + STEMS-4 file + sidecar OK. ffprobe is
already checked before separating (1.0).

Packaging (item 9 class): the apps never shipped `build/lighttext`,
`build/touchfx`, `build/fx` -> deck steps 5l (light mode) and 5x (TOUCH FX)
would fail exactly like the 0.9.x centre-module report. Added to
`tools/build_studio.sh` and the public repo's `prebuilt/deck` list.

RGB grid off-axis (item 7): NOT reproduced. Rekordbox's colour data lines
up with the blue data (40 tracks, 0-entry offset), and in the emulator the
RGB column reads exactly the painter's own 4-entry window (r8 advances 32 =
4 entries per column, step 4). Needs a photo/video from the reporter.

3-band "falls back to blue" (item 5): the UTILITY/MY SETTINGS rows ignore
changes while MODS = OFF (by design); and a track without PWV6/PWV7 draws
stock blue. Ask which of the two it is.
